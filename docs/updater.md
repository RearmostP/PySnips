# המעדכן העצמאי

`PySnips.exe` נבנית כ־ONEDIR. היא קוראת גרסה דרך `core/common/version.py`
ומשגרת תהליך `QProcess` דרך `core/common/update_process.py`. היא אינה מייבאת
את `core/updater` ואינה מבצעת בקשות רשת או מתקינה עדכונים.

`PySnipsUpdater.exe` נבנית כ־ONEFILE, עם Python, Qt, השפות, QSS, אייקון
ומטא־נתוני גרסה משלה. `core/updater/app.py` מנהל את חלון העדכון;
`updater.py` מבצע בדיקה, הורדה ואימות; `handoff.py` מנהל את ההעברה וההתקנה.
המתקין היחיד נשאר Inno Setup.

## בדיקה והורדה

ארבע שניות לאחר הצגת החלון הראשי מופעל `--check-silent`. ללא עדכון או בשגיאת
בדיקת רשת הוא יוצא בלי להציג חלון. עדכון זמין מוצג ללא התחלת הורדה אוטומטית.
כפתור ההגדרות מפעיל `--check`, המציג בדיקה ותוצאה או שגיאה. השפה הנוכחית,
נתיב היישום ו־PID נמסרים למשגר. רק תהליך עדכון אחד משוגר מכל חלון ראשי.

העבודה מתבצעת ב־QThread קטן. ההורדה משתמשת במקטעי 64 KiB וב־Content-Length
אם הוא קיים, ומדווחת בתים אמיתיים. ללא גודל ידוע פס ההתקדמות אינו קצוב.
המתקין נשמר כ־`.exe.part`; checksum יחיד בן 64 תווים נשלף מנכס `.sha256`
ונבדק מול גיבוב המחושב במקטעים. רק לאחר הצלחה הקובץ מקודם לשם המלא.
כל ניסיון GUI מקבל תיקיית session נפרדת. קובץ מאומת קיים אינו נמחק בכשל.

זמן תחילת השלב נשמר באמצעות `time.monotonic`. לאחר הורדה ואימות,
`remaining_download_ms` מחשב את הזמן שנותר לשתי שניות, ו־QTimer מבצע את
המעבר למצב מוכן. אין האטת הורדה או אחוזים מומצאים. בדיקות הזמן משתמשות
בערכים מוזרקים ואינן ממתינות שתי שניות.

## הפעלה מחדש והתקנה

סגירת חלון העדכון במצב זמין או מוכן אינה מתקינה דבר ואינה סוגרת את PySnips.
בהורדה או בהתקנה לא ניתן לסגור את החלון עד לסיום העבודה, כדי לא לנטוש thread
או מתקין פעיל. „הפעלה מחדש ועדכון” היא הפעולה היחידה שיוזמת העברה.

העותק המותקן מעתיק את `sys.executable` לתיקיית
`%TEMP%\PySnips\update-session-<unique>`, ומשגר אותו עם `--apply-update`.
נמסרים session, מתקין, גרסת יעד, checksum שכבר אומת, נתיב PySnips ו־PID של
PySnips והמעדכן המקורי. העותק הזמני מאמת את הקובץ ומסמן `coordinator.ready`.
רק לאחר האישור יוצא המעדכן המקורי עם `RESTART_UPDATE_EXIT_CODE = 42`.
PySnips רואה יציאה תקינה בקוד זה וקוראת `QApplication.quit()`.
כשל לפני ההעברה אינו סוגר אותה. אישור שלא הגיע בתוך 20 שניות מסמן העברה
מבוטלת; עותק שעלה באיחור אינו רשאי להתקין.

העותק הזמני ממתין עד 60 שניות לכל PID בלי להפסיק אותו בכוח. ב־ONEFILE נמסר
PID של bootloader המעדכן המקורי, כדי להמתין גם לשחרור קובץ ההפעלה המותקן.
לאחר ההמתנה checksum נבדק שוב, ואז מופעל Setup עם:

```text
/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART /RESTARTEXITCODE=3010
/NOCLOSEAPPLICATIONS /NORESTARTAPPLICATIONS /DIR=<existing-install-directory> /LOG
```

חלון המעדכן מציג „מתקין את העדכון”. ההמתנה למתקין מוגבלת ל־15 דקות.
רק exit code 0 גורם להפעלת PySnips החדשה. קוד 3010 (נדרש אתחול מערכת),
קוד כשל, timeout או כשל הפעלה מחדש מוצגים כשגיאה. אין ניסיון נוסף אוטומטי.
ב־timeout המתקין אינו מופסק בכוח; מוצגת אזהרה שהוא עשוי עדיין לפעול.
ה־Setup כולל גם את המעדכן החדש, ולכן מחליף את המעדכן המותקן בזמן שהמתאם
רץ מתוך TEMP. אין מערכת עדכון עצמית נוספת.

המשגר מאפס את סביבת PyInstaller עבור תהליך עצמאי; לפני הפעלת Setup מנוקה
גם נתיב חיפוש ה־DLL של Windows. זהות AppId, הגרסה 0.2.0, בחירת תיקייה
באשף הרגיל ו־`skipifsilent` לא שונו. הפעלה ידנית של Setup נשארת רגילה.

session פעיל אינו נמחק. בהפעלות עתידיות יש ניקוי מיטבי של sessions בני
שבעה ימים לפחות שאין להם PID חי ושל קובצי `.part` ישנים. כשל ניקוי אינו
חוסם עדכון. המעדכן הזמני אינו מנסה למחוק את קובץ ההפעלה של עצמו.

## פיתוח ובדיקות

```powershell
python -m core.updater --check --language he
python -m core.updater --check-silent --language en
$env:QT_QPA_PLATFORM = 'offscreen'
python -m unittest discover -s tests -v
```

משגר PySnips משתמש ב־Python הנוכחי וב־`-m core.updater` במצב מקור. בניית
פקודת ההעברה במצב מקור גם היא משגרת את המודול, ואינה מעתיקה את python.exe.
בדיקות המתאם מזריקות תהליכי Setup והפעלה מחדש, ללא רשת או התקנה אמיתית.
בדיקת UI, הורדה ואימות אפשריים בלי build. כדי לא לדרוס את תיקיית המקור,
„הפעלה מחדש ועדכון” כאשר נתיב היישום הוא `main.py` מציגה הסבר ומשאירה את
PySnips פתוחה. בדיקת התקנה ממשית דורשת התקנה ארוזה מבודדת; ניתן לבחון
את אותו מתאם מתוך Python עם `--app-path` של עותק ארוז מבודד.

קובצי ההפעלה אינם חתומים. ה־checksum מגן על שלמות ביחס לנכס GitHub,
ואינו חתימה קריפטוגרפית של המפרסם. אין לפרסם build ניסויי זה כגרסת 0.2.0.
