# PySnips V2 — מבנה והבדלים מהמקור

## המקור שנבדק

נבדקה מפת הקבצים המלאה של [RearmostP/PySnips](https://github.com/RearmostP/PySnips),
ונקראו קובצי Python, ממשקי Designer, ההגדרות והתיעוד בגרסה
`8339fd49a5d2a6328ad45c8e28a7e99844572a57`.
לא היו במפה זו בדיקות רגרסיה קיימות.

התיקייה המקומית בתחילת העבודה הכילה `main.py` ריק ושלד ממשקים ריק, ולא
checkout של המקור הישן. לכן מדובר במימוש V2 בתיקייה המקומית; לא בוצעה מחיקה
של קבצים או נתוני משתמש בריפוזיטורי המרוחק.

## מה הושמט ומה נכתב מחדש

- Ready Code וכל הנתיבים, הממשקים וההגדרות התלויים בו לא הועברו.
- ScreenManager, רישום מסכים והזרקת מנהל הוחלפו בניווט ישיר בחלון הראשי.
- טעינה באמצעות מפעל מחלקות, ניתוח XML ומפת קבצים מרכזית הוחלפה בקריאה
  ישירה ל־QUiLoader בכל רכיב, עם קובץ `.ui` סמוך.
- boot, integrity, mapping ואכיפת שמות רכיבים אינם חלק מהאפליקציה.
- מערכת דיבוג, hooks, כתיבת לוגים וניתוח tracebacks לא הועברו.
- אשפה מורכבת, אשפת קטגוריות, זמני שמירה וניקוי אוטומטי לא הועברו.
- MarkdownService, cache והגדרות רינדור מרובות הוחלפו בעיבוד ורינדור קטנים.
- נשמר רעיון הכתיבה האטומית עם קובץ זמני באותה תיקייה, fsync ו־os.replace.
- נשמרו UUID, הפרדת שם תצוגה משם בדיסק, ניקוי תגיות, חיפוש תחילת מילה,
  כותרות ותגיות. החיפוש כולל כעת גם תוכן Markdown.

## המבנה הנוכחי

```text
main.py
core/
├── ui/
│   ├── main_window.py
│   ├── home/                 # Python + Designer
│   ├── snips/
│   │   ├── widgets/          # כרטיס ורכיב חיפוש
│   │   └── dialogs/          # יצירה/עריכה, פרטים ואשפה
│   └── settings/pages/       # הגדרות כלליות ופעולות שליפים
├── snips/                    # library.py, models.py, search.py
├── markdown/                 # processor.py, renderer.py
├── settings/                 # ברירות מחדל ו־JSON
├── localization/             # מילון ותרגום רכיבי UI
├── theme/                    # החלת QSS על QApplication
└── common/                   # שורשי נתיבים, כתיבה אטומית והודעות GUI
assets/
├── languages/                # en.lang, he.lang
└── themes/                   # dark/light/style.qss
tests/
docs/
```

הרכיבים הועברו רעיונית מארגון `screens/ui` מול `screens/ui_logic` לארגון
לפי רכיב. הממשקים מותאמים מקובצי ה־Designer המקוריים, עם טקסט אנגלי
ב־Designer ומפתחות `i18nKey`. סרגל הקטגוריות, הפריסה, כרטיסי התוכן ועורך
ה־Markdown משחזרים את מבנה המקור. העיצוב הועבר מהקוד הישן ל־QSS המרכזי.
הדיאלוג ליצירה משמש גם לעריכה, במקום עורך כרטיס נפרד.

`MainWindow` מחזיק שלושה מסכים בתוך `QStackedWidget`, עם `show_home`,
`show_snips`, `show_settings`. הקשרים בין המסכים הם signals מפורשים.
רק `SnippetLibrary` קורא וכותב נתוני שליפים, מעביר תיקיות ומפעיל חיפוש.
`SearchIndex` הוא רכיב פנימי קטן משום ש־Whoosh הוא אחריות נפרדת מהאחסון.

## אחסון וחיפוש

ביצירה נבנית תיקייה זמנית עם כל הקבצים והמדיה, ואז שמה מוחלף לשם הסופי.
בהעברה עוברת כל תיקיית השליף, ולא רק קובץ התוכן. אם כתיבת המטא־דאטה
לאחר העברה נכשלת, התיקייה מוחזרת למקומה. התנגשות שמות אינה דורסת נתונים.
מחיקה רגילה מעבירה את אותה תיקייה לאשפה תחת ה־UUID. שחזור שומר על המזהה.

רק קטגוריות שנמצאות ב־`categories.json` מוצגות ונקראות. תיקיות שלהן נוצרות
מחדש אם חסרות. תיקייה בלתי רשומה אינה מתווספת כקטגוריה מעצמה.
קובצי מטא־דאטה פגומים או מזהים כפולים גורמים לשגיאת נתונים מפורשת.
קישורים סימבוליים ו־junctions בתוך הספרייה אינם נתמכים.

האינדקס מכיל מידע נגזר בלבד. fingerprint קטן לצד האינדקס מוודא שהוא
מתאים לתוכן הקבצים; גם עריכה חיצונית מזוהה בחיפוש הבא. שמירה מעדכנת את
האינדקס באמצעות בנייה מחדש, בחירה פשוטה לספרייה המקומית הראשונית.
אם כתיבת האינדקס נכשלת, נתוני השליף נשארים שמורים, והחיפוש הבא מנסה
לבנות אותו שוב. האינדקס אינו נבנה מחדש בכל הפעלה.

Whoosh 2.7.4 מחזיק לעיתים קובץ TOC פתוח לאחר כשל קריאה ב־Windows.
התאמת אחסון קטנה קוראת רק את קובץ ה־TOC לזיכרון וסוגרת מיד את הקובץ
בדיסק. קובצי מקטעים נכתבים בנפרד ללא mmap, כדי לשחרר ידיות באופן צפוי
ב־Windows/Python 3.14. זו התאמת ספרייה פנימית, לא שכבת אחסון של שליפים.

## שפות וערכות נושא

`en.lang` ו־`he.lang` הם UTF-8 בפורמט `key = value`; שורות ריקות והערות
שמתחילות ב־`#` מדולגות. `\n` בתוך ערך מייצג מעבר שורה.
ה־UI שומר את טקסט ה־Designer המקורי, כדי שגם אחרי החלפת שפה מפתח חסר
יחזור לאנגלית ולא יישאר עם תרגום מהשפה הקודמת.
טקסט שנוצר בקוד משתמש במפתחות מאותו מילון.

התרגום מטפל גם בכיוון הפריסה. עורכי קוד מסומנים ב־`codeEditor` ושומרים על
LTR. בלוקי קוד מרונדרים כ־LTR גם כשהממשק עברי.
נוספו `i18nPlaceholderKey` לשדות הקלט ותמיכה בכותרות/tooltips.
שפה נוספת היא קובץ `.lang` נוסף; RTL נתמך כרגע בעברית בלבד.

ערכות הנושא מתגלות מתיקיות שמכילות `style.qss`, וכל QSS מוחל על האפליקציה.
רינדור Markdown משתמש בצבעי ה־palette ובסגנון Pygments מתאים לבהירותו.
אין צבעי ממשק בקוד המסכים או בקובצי Designer.

## מגבלות ומאפיינים שנדחו במכוון

- cache, frameworks לאתחול, כלי פיתוח, מנגנון שגיאות גלובלי ותחזוקת אשפה
  אוטומטית אינם ממומשים.
- הממשק משתמש בפריסות המקור עם התאמות ל־V2: הגדרות מחליפות את הקוד
  המוכן בבית; הגדרות הן מסך ראשי; אשפה היא דיאלוג ללא זמני שמירה.
  אין כרגע הצמדת קטגוריות, הגדרת גובה כרטיסים או ניהול
  מחיקה/שינוי שם של קטגוריות.
- אין transactions בין קובצי התוכן והמטא־דאטה. כל קובץ נכתב אטומית,
  אך הפסקת חשמל באמצע עדכון משולב יכולה להשאיר חלקים מעדכון בשלבים שונים.
- נתמכת הרצה של מופע יחיד. אין נעילה בין כמה מופעי PySnips.
- צירוף מדיה לשליף קיים מעתיק את הקובץ מיד. ביטול העריכה אינו מוחק את
  הקובץ המצורף; הוא עשוי להישאר בלתי מקושר. צירוף ביצירה נשמר רק בשמירה.
- אין אריזה למתקין או החלטה קבועה על תיקיית הנתונים במצב installed.
  `PYSNIPS_DATA_DIR` מאפשר להפריד כבר עכשיו נתונים מקובצי האפליקציה.
- פונט JetBrains Mono, אייקון האפליקציה ואייקוני ניווט ההגדרות הועתקו
  מהמקור אל `assets/`. אפשר להוסיף פונטים אחרים אל `assets/fonts`.

## תאימות ומעבר נתונים

הפורמט הישן (`categorys.json`, `snips_files/<category>/snips.json` וקובצי
Markdown נפרדים עם `content_file`) אינו נקרא אוטומטית ב־V2.
אין importer אוטומטי ואין שינוי בנתונים הישנים.

לפני מעבר יש לגבות את כל `data/user_data` הישן. לכל רשומה יש לשמר את
`id`, הכותרת, התגיות ותאריך היצירה, לבחור `disk_name` תקין, להעתיק את
התוכן אל `snippet.md`, וליצור `metadata.json` קטן ו־`media/`.
הקטגוריות צריכות להירשם ב־`categories.json`. נתיבי תמונות יש להמיר
לנתיבים יחסיים לאחר העתקת הקבצים אל `media/`. אין להעתיק את אינדקס
Whoosh, את cache ה־HTML או את ההגדרות הישנות; V2 ייצור את נתוני התמיכה שלו.

מומלץ לבחור תיקיית V2 נפרדת בעזרת `PYSNIPS_DATA_DIR`, ולא להפנות אותה
ישירות לתיקיית נתונים ישנה. הוספת כלי יבוא מפורש יכולה להיות צעד נפרד
לאחר בדיקה של נתוני המשתמש בפועל.
